# 跨平台对标账号浏览器搜索技术方案

## 1. 目标

建立“在线搜索账号 → 获取账号详情 → 获取公开帖子 → 生成订阅源 → 验证 → 加入画像 → 沉淀动态账号池”的统一能力。

浏览器方案优先用于没有稳定公开账号搜索 API 的平台。B 站等已有公开 API 的平台仍优先使用 API，浏览器作为降级。

## 2. 统一执行链路

```text
输入平台与关键词
  → 检查持久化浏览器登录状态
  → 打开平台 Web 搜索页
  → 进入“用户/作者”分类
  → 优先捕获搜索网络响应 JSON
  → DOM 解析作为降级
  → 输出标准化用户列表
  → 用户选择账号
  → 直接打开账号主页
  → 捕获用户详情和帖子分页响应
  → DOM 解析作为降级
  → 生成 RSSHub 路由
  → 使用 Folo/RSSHub 验证 Feed
  → 加入当前画像
  → 验证成功后写入动态账号池
```

不应依赖逐个鼠标点击头像。搜索结果中能够提取主页 URL 时，直接导航到主页；只有拿不到 URL 时才用点击降级。

## 4. 平台 Web 路径与可获取数据

### 4.1 小红书

搜索页：

```text
https://www.xiaohongshu.com/search_result?keyword={keyword}&source=web_search_result_notes&type=51
```

主页：

```text
https://www.xiaohongshu.com/user/profile/{user_id}?xsec_token={token}&xsec_source=pc_search
```

RSSHub：

```text
/xiaohongshu/user/{user_id}/notes
```

搜索阶段可获取：昵称、头像、`user_id`、主页地址、简介、粉丝、获赞与收藏、`xsec_token`、认证信息。

主页阶段可获取：小红书号、IP 属地、简介、性别/年龄等公开资料、关注数、粉丝数、获赞与收藏、公开笔记 ID、标题、封面、链接、类型和互动数据。

要求：搜索结果需要登录；部分主页正文在未登录时仍可能渲染，但帖子列表受限。`xsec_token` 用于访问上下文，不作为账号唯一标识。

### 4.2 抖音

搜索页：

```text
https://www.douyin.com/search/{keyword}?type=user
```

主页：

```text
https://www.douyin.com/user/{sec_uid}?from_tab_name=main
```

RSSHub：

```text
/douyin/user/{sec_uid}
```

搜索阶段可获取：昵称、头像、`sec_uid`、抖音号、主页地址、简介、粉丝、获赞、作品数、认证信息、直播状态。

主页阶段可获取：昵称、抖音号、`sec_uid`、简介、粉丝、关注、获赞、作品总数、公开作品 ID、描述、链接、封面、发布时间、点赞/评论/收藏/分享。

要求：搜索需要登录；主页基础资料可能未登录可见，作品列表可能返回“服务异常”或受登录限制。不要自行维护 `a_bogus`，由真实浏览器页面产生平台签名。

### 4.3 B 站

搜索页：

```text
https://search.bilibili.com/upuser?keyword={keyword}
```

主页：

```text
https://space.bilibili.com/{mid}
https://space.bilibili.com/{mid}/upload/video
https://space.bilibili.com/{mid}/dynamic
```

RSSHub：

```text
/bilibili/user/dynamic/{mid}
/bilibili/user/video/{mid}
```

搜索阶段可获取：`mid`、昵称、头像、简介、粉丝数、视频数、等级、认证信息、主页地址。

主页阶段可获取：昵称、关注数、粉丝数、投稿总数、动态、视频/图文/音频数量、BV 号、标题、播放量、弹幕、时长、发布时间、封面。

要求：未登录可以搜索并查看大量公开结果。正式实现优先使用现有公开搜索 API，Web 浏览器作为降级和字段补全。

### 4.4 微博

搜索页：

```text
https://s.weibo.com/user?q={keyword}
```

主页：

```text
https://weibo.com/u/{uid}
https://m.weibo.cn/u/{uid}
```

RSSHub：

```text
/weibo/user/{uid}
```

搜索阶段可获取：UID、昵称、头像、粉丝数、认证类型、认证描述、简介、学校/公司/地区等公开信息。

主页阶段可获取：昵称、粉丝数、关注数、转评赞、认证、简介、公开微博、微博链接、发布时间、转发/评论/点赞、图片和视频。

要求：未登录可以看到一部分用户搜索结果和账号概览；更多结果与微博正文要求登录。适合“网络响应优先 + DOM 降级”。

### 4.5 知乎

搜索页：

```text
https://www.zhihu.com/search?type=people&q={keyword}
```

主页：

```text
https://www.zhihu.com/people/{id}
https://www.zhihu.com/people/{id}/answers
https://www.zhihu.com/people/{id}/posts
https://www.zhihu.com/people/{id}/zvideos
https://www.zhihu.com/people/{id}/pins
```

RSSHub：

```text
/zhihu/people/activities/{id}
```

搜索阶段预期可获取：用户 ID、昵称、头像、简介、关注者、回答/文章数量和认证。

主页阶段可获取：昵称、IP 属地、简介、教育/职业、关注者、赞同/喜欢/收藏总量、回答/文章/视频/想法数量、公开回答和文章链接。

要求：本轮未登录实测搜索页返回“未搜索到相关用户”，但已知主页可读取完整账号概览；文章正文列表提示登录。因此搜索 Provider 需要持久化登录态，主页基础信息可无登录降级。

### 4.6 今日头条

搜索页：

```text
https://www.toutiao.com/search/?keyword={keyword}
https://so.toutiao.com/search/?dvpf=pc&keyword={keyword}
```

主页：

```text
https://www.toutiao.com/c/user/token/{token}/
```

RSSHub：

```text
/toutiao/user/token/{token}
```

搜索阶段预期可获取：账号名、头像、用户 token、认证、简介、粉丝和主页地址。搜索页可能混合全网结果，需切换“用户”分类并捕获对应网络响应。

主页阶段可获取：账号名、获赞、粉丝、关注、认证、简介、文章/视频/微头条/小视频列表、标题、内容摘要、播放/阅读、评论和发布时间。

要求：`so.toutiao.com` 部分入口会尝试跳转 `snssdk143://`，必须禁止 App Scheme 跳转并固定 PC 搜索入口。已知 token 的主页在未登录时可稳定读取公开内容。

### 4.7 微信公众号

搜索页（第三方）：

```text
https://weixin.sogou.com/weixin?type=1&query={keyword}
```

文章页：

```text
https://mp.weixin.qq.com/s/{article_id}
https://mp.weixin.qq.com/s?__biz={biz}&mid=...&idx=...&sn=...
```

RSSHub：

```text
/wechat/mp/{__biz_or_newrank_id}
```

搜索阶段预期可获取：公众号名称、头像、微信号、功能介绍、认证主体、最近文章和文章链接。

文章阶段可获取：`__biz`、公众号名称、文章标题、作者、发布时间、正文和公众号跳转参数。

要求：微信没有官方 Web 账号搜索；搜狗结果受认证状态、频控和验证码影响。本轮实测“机器之心”和“github”都未返回认证订阅号，不能作为唯一数据源。应采用“公众号文章链接反查 + Folo/已有 Feed + 搜狗可选搜索”。

### 4.8 快手

搜索页：

```text
https://www.kuaishou.com/search/author?searchKey={keyword}
```

主页：

```text
https://www.kuaishou.com/profile/{user_id}
```

搜索阶段预期可获取：用户 ID、昵称、头像、简介、粉丝、作品数和主页地址。

主页阶段预期可获取：账号资料和公开短视频列表，包括 photo ID、标题、封面、播放与互动。

要求：本轮未登录页面只显示搜索框和“用户”入口，没有渲染用户列表；需要持久化登录后继续验证。当前对标 RSSHub 模板尚未包含快手，第一版可先保存主页和浏览器帖子，不强制生成 RSSHub。

### 4.9 36氪

搜索页：

```text
https://36kr.com/search/articles/{keyword}
```

内容页：

```text
https://36kr.com/p/{article_id}
```

RSSHub：

```text
/36kr/newsflashes
```

可获取：搜索文章标题、摘要、发布时间、作者/企业号、文章 ID、正文链接；作者搜索能力弱于内容搜索，更适合作为站点内容源而非个人账号池。

要求：页面加载较慢，`load` 事件可能超时，但 DOM 在 `interactive` 状态已可解析。实现时应等待目标内容元素，不等待全页 `load`。

### 4.10 视频号

入口：

```text
https://channels.weixin.qq.com/platform
```

这是创作者后台，不是公开的跨账号搜索入口。可读取当前登录账号数据，但不适合发现其他对标账号。对标发现应通过用户分享的视频号链接、人工导入或授权数据源实现。

## 6. 浏览器实现原则

1. 使用平台独立的 Playwright 持久化 Profile，复用现有发布和账号数据模块登录态。
2. 搜索和主页读取优先捕获页面已签名的网络响应 JSON，不自行逆向动态签名。
3. DOM 解析作为降级，选择器优先使用稳定 href、语义文字和数据属性，不依赖混淆 class。
4. 发现验证码、扫码或风控时停止自动操作，状态返回 `login_required` 或 `blocked`，交给用户处理。
5. 同一平台 Profile 使用进程锁，禁止发布和搜索同时打开。
6. 搜索一次最多 20～50 个账号；仅对用户选择的账号深入读取主页。
7. 首次添加默认读取最近 30 条帖子，手动深度同步最多 100 条；后续只增量抓取。
8. 账号唯一标识使用平台稳定 ID，不使用 `xsec_token`、短期签名或昵称。
9. Cookie、storage state 和 token 只留在浏览器 Profile，不进入 API 响应和账号池。
10. 所有上游数据标记来源、抓取时间和可信度。

## 9. 分阶段实施

### 阶段 A：浏览器基础设施

- 复用现有平台 Playwright Profile；
- 登录状态检查；
- 有头登录窗口；
- Profile 互斥锁；
- 异步任务状态；
- 统一输出模型。

### 阶段 B：第一批 Provider

- 小红书：登录、用户搜索、主页详情、最近笔记；
- 抖音：登录、用户搜索、主页详情、最近作品；
- 微博：匿名搜索优先、登录补全帖子；
- 知乎：登录搜索、主页资料、回答和文章；
- 头条：PC 用户搜索、主页和帖子。

### 阶段 C：特殊来源

- 公众号文章反查；
- 搜狗微信可选搜索；
- 快手已登录搜索；
- 36氪内容源；
- RSSHub Radar 自动路由；
- Folo Feed 缓存验证。

### 阶段 D：前端统一入口

```text
在线搜索 | 粘贴链接 | 推荐账号池
```

平台下拉展示每个平台的状态：`API 可用`、`浏览器已登录`、`需要登录`、`暂不可用`。

## 10. 验收标准

1. B 站、微博匿名环境能够返回真实账号搜索结果。
2. 小红书、抖音、知乎在完成扫码/登录后能够返回用户列表。
3. 搜索结果至少包含稳定用户 ID、名称、头像、主页地址和可获取的粉丝信息。
4. 选择用户后能读取账号详情和最近公开帖子。
5. 用户搜索结果不会被推荐内容污染，帖子必须校验作者 ID。
6. 账号可转换为现有统一数据模型并加入画像。
7. 已验证账号自动沉淀动态账号池并去重。
8. 登录过期、验证码、风控、上游超时均有明确状态。
9. 不泄露 Cookie、Token 和浏览器存储。
10. 浏览器失败时保留现有 API、RSSHub、Folo 和公开页降级能力。
