# 垂直领域视频生成器技术方案

> 文档类型：技术设计方案
>
> 范围：电商宣传视频、企业推广视频的极简生成
>
> 核心理念：**极简输入、深度输出**——用户只需"需求描述 + 图片素材"，系统自动产出高质量垂直领域视频

---

## 1. 核心理念

```
用户输入:  需求描述 + 图片素材
            ↓
系统自动:  理解领域 → 写专业脚本 → 智能配图 → 专业配音 → 选曲 → 设计字幕 → 合成
            ↓
用户得到:  高质量垂直领域视频
```

**不做**：事实库、项目管理、审批流、Brief 表单、多角色协作
**只做**：把"需求+图片"变成"高质量领域视频"这一件事做到极致

### 设计原则

1. **极简输入**：用户操作不超过 4 步，30 秒内完成输入
2. **深度输出**：不是通用口播视频，而是电商/企业专用结构的转化型视频
3. **复用现有能力**：不重写 114 个 Skill，在其上叠加领域专用编排层
4. **质量优先**：脚本结构、画面策略、配音BGM、文字叠加都按领域深度定制

## 2. 用户操作流程

### 2.1 完整流程

```
1. 选择领域: [电商宣传] 或 [企业推广]     ← 1 次点击
2. 输入需求: 一句话描述你要宣传什么        ← 1 句话
   例: "智能水杯，卖点是提醒喝水、316不锈钢、保温12小时"
   例: "我们做企业IT运维，帮客户降本增效，有ISO认证"
3. 上传图片: 拖入产品图/场景图/Logo        ← 拖拽
   可选: 不传图也行，系统用AI生图或设计卡片
4. 选择画幅: 竖版(9:16) / 横版(16:9)       ← 默认竖版
5. 点击生成 → 等待 → 预览 → 满意就下载     ← 1 次点击
```

**总操作**：选领域 + 打一句话 + 拖图 + 点生成 = **4 步，30 秒**

## 3. 两个领域的深度设计

### 3.1 电商宣传视频

#### 脚本结构（电商转化专用 6 阶段）

| 阶段 | 时长 | 目标 | 电商专用技巧 |
|---|---|---|---|
| Hook | 0-3s | 抓住注意力 | 痛点场景 / 产品惊艳亮相 / 价格冲击 |
| 痛点共鸣 | 3-8s | 让用户觉得"这是我" | 具体生活场景 + 真实困扰 |
| 产品亮相 | 8-15s | 展示解决方案 | 产品特写 + 核心卖点(1-2个) |
| 卖点展开 | 15-25s | 建立购买理由 | 卖点→好处→场景 3层转化 |
| 信任背书 | 25-28s | 打消顾虑 | 材质/认证/销量/评价 |
| 行动号召 | 28-30s | 促转化 | 限时/优惠/明确CTA |

示例：

```
[0-3s] HOOK
口播: "总是忘记喝水？这个杯子会提醒你"
画面: 用户提供的痛点场景图 → Ken Burns 缓推
叠加: 大字痛点文案 "总是忘记喝水？"

[3-8s] 痛点共鸣
口播: "开会一忙就忘，等想起来水都凉了"
画面: 生活场景图 → Ken Burns
叠加: 无

[8-15s] 产品亮相
口播: "智能水杯Pro，定时提醒，316不锈钢"
画面: 产品白底图/主图 → static 居中 + 背景渐变
叠加: 产品名 + 核心卖点 "智能水杯Pro"

[15-25s] 卖点展开
口播: "保温12小时，早上倒的热水，下午还温的"
画面: 产品细节图/场景图 → Ken Burns + 文字标注
叠加: 卖点关键词高亮 "316不锈钢" "保温12小时"

[25-28s] 信任背书
口播: "食品级316不锈钢，月销10000+"
画面: 认证图/评价截图/销量数据 → static + 数字动画
叠加: 数据卡片 "月销10000+" "食品级认证"

[28-30s] 行动号召
口播: "现在下单立减40，点击下方链接"
画面: 产品图 + 价格/优惠 → static + 促销信息
叠加: 价格 + 行动按钮样式 "¥159 立即购买" "限时立减40"
```

#### 画面策略

| 分镜类型 | 画面处理 | 文字叠加 |
|---|---|---|
| Hook镜 | 用户痛点场景图 → Ken Burns 缓推 | 大字痛点文案 |
| 产品亮相 | 产品白底图/主图 → 居中 static + 背景渐变 | 产品名 + 核心卖点 |
| 卖点展示 | 产品细节图/场景图 → Ken Burns + 文字标注 | 卖点关键词高亮 |
| 信任背书 | 认证图/评价截图/销量数据 → static + 数字动画 | 数据卡片 |
| CTA镜 | 产品图 + 价格/优惠 → static + 促销信息 | 价格 + 行动按钮样式 |

#### 配音策略

| 内容类型 | 音色 | 语速 | 情绪 |
|---|---|---|---|
| 电商宣传 | 专业女声(晓晓) 或 活力男声 | 偏快(1.1x) | 热情、有说服力 |
| 价格/优惠处 | 语速放慢 + 重音 | 0.9x | 强调感 |

#### BGM 策略

| 场景 | 音乐风格 | 情绪 |
|---|---|---|
| 通用电商 | 轻快电子/Pop | 活力、现代 |
| 高端商品 | 质感电子/Ambient | 品质感 |
| 促销活动 | 节奏感强/鼓点 | 紧迫感 |

### 4.4 智能配图：用户图片 → 分镜匹配

这是质量的关键。用户拖入 N 张图，系统需要智能分配到脚本分镜：

```python

    """
    用户图片 → 脚本分镜的智能匹配。

    匹配策略（按优先级）:
    1. 图片元信息匹配:
       - 文件名含"产品/主图/白底" → 产品亮相镜

       - 自动 pad 到目标画幅
       - 产品图用 static（不裁切）

    """
```

### 5.2 后端实现

```python
# web/app.py 新增

@app.post("/api/video/generate")
async def api_video_generate(req: VideoGenRequest):
    job_id = f'video_{int(time.time())}_{uuid.uuid4().hex[:6]}'
    # 保存图片到临时目录
    img_dir = OUTPUTS_DIR / job_id / "input_images"
    img_dir.mkdir(parents=True, exist_ok=True)
    for upload_id in req.images:
        # 从上传目录复制图片
        ...
    # 启动后台生成
    threading.Thread(
        target=_run_video_gen,
        args=(job_id, req, img_dir),
        daemon=True
    ).start()
    return {"job_id": job_id, "status": "running"}

def _run_video_gen(job_id, req, img_dir):
    """
    后台执行视频生成，参考现有 _run_job (发布Job) 模式。
    逐步执行，更新状态文件。
    """
    job_dir = OUTPUTS_DIR / job_id
    state_file = job_dir / "state.json"

    def update(step, progress, message, eta):
        _save_json(state_file, {
            "job_id": job_id, "status": "running",
            "progress": progress, "current_step": message, "eta_seconds": eta
        })

    # Step 1: 生成脚本
    update(1, 10, "理解需求，生成专业脚本", 30)
    script = _gen_domain_script(req.domain, req.requirement, req.duration)

    # Step 2: 智能配图
    update(2, 30, "智能匹配图片到分镜", 5)
    shots = _map_images_to_shots(img_dir, script["shots"], req.aspect)

    # Step 3: 文字叠加
    update(3, 40, "设计画面文字", 10)
    for shot in shots:
        if shot.get("overlay"):
            _overlay_text(shot["image"], shot["overlay"])

    # Step 4: 配音
    update(4, 55, "AI配音中", 15)
    voice_path = _gen_voiceover(script["full_text"], req.domain, job_dir)

    # Step 5: BGM
    update(5, 70, "选曲配乐", 3)
    bgm_path = _select_bgm(req.domain, script["tone"])

    # Step 6: 合成
    update(6, 85, "合成成片中", 20)
    storyboard = _build_storyboard(shots, voice_path, bgm_path, req.aspect)
    _run_assemble(storyboard, job_dir / "final.mp4")

    # 完成
    update(6, 100, "完成", 0)
    _save_json(state_file, {
        "job_id": job_id, "status": "done", "progress": 100,
        "result": {
            "video_path": str(job_dir / "final.mp4"),
            "script": script["full_text"],
            "used_images": sum(1 for s in shots if s.get("source") == "user"),
            "ai_generated_images": sum(1 for s in shots if s.get("source") == "ai"),
            "voice": script["voice_name"],
            "bgm": script["bgm_name"]
        }
    })
```

### 5.3 脚本生成：领域模板驱动

```python
def _gen_domain_script(domain, requirement, duration):
    """
    用领域专用模板生成脚本，而非通用 video-script。

    电商模板 (references/script-templates.md):
    - 6阶段结构: Hook → 痛点 → 产品亮相 → 卖点展开 → 信任背书 → CTA
    - 每阶段有字数比例、画面类型、文字叠加规格

    企业模板:
    - 5阶段结构: Hook → 问题展开 → 方案介绍 → 实力证明 → CTA
    - 每阶段有字数比例、画面类型、文字叠加规格
    """
    template = load_template(domain, duration)
    # 构造 Prompt: 模板 + 需求 → LLM 生成结构化脚本
    prompt = f"""
    你是专业的{domain == 'ecommerce' and '电商' or '企业'}视频文案。
    根据以下模板和需求，生成一条{duration}秒视频的完整脚本。

    ## 脚本模板
    {template}

    ## 用户需求
    {requirement}

    ## 输出格式（JSON）
    {{
        "full_text": "完整口播文案",
        "voice_name": "推荐音色名",
        "bgm_style": "推荐BGM风格",
        "shots": [
            {{
                "phase": "hook",
                "narration": "口播文案",
                "caption": "字幕",
                "visual_type": "scene|product|detail|trust|cta",
                "image_source": "user|ai|card",
                "overlay": {{
                    "type": "price|selling_point|data|cta",
                    "text": "叠加文字",
                    "style": "样式预设名"
                }},
                "duration": 3.0,
                "motion": "ken-burns|static"
            }}
        ]
    }}
    """
    # 调用 LLM (通过现有 /api/chat 或直接调 openclaw)
    return call_llm(prompt)
```

## 7. 质量保障机制

### 7.1 脚本质量

| 检查项 | 方法 |
|---|---|
| 字数匹配时长 | `wordcount.py check` (250字/分钟) |
| 结构完整 | 电商6阶段/企业5阶段是否齐全 |
| Hook强度 | 3秒内是否有信息冲击 |
| CTA明确 | 结尾是否有明确行动引导 |
| 口语化 | 短句、无书面语、可朗读 |

### 7.2 画面质量

| 检查项 | 方法 |
|---|---|
| 图片充足 | 分镜数 vs 图片数，不足时AI/卡片补充 |
| 图片匹配 | 分镜类型 vs 图片类型不矛盾 |
| 文字叠加可读 | 叠加文字不遮挡图片关键内容 |
| 画幅一致 | 所有图片pad到统一画幅 |

### 7.3 音频质量

| 检查项 | 方法 |
|---|---|
| 配音完整 | TTS无失败句 |
| 音量平衡 | 配音 vs BGM 比例合理 (BGM 0.15-0.25) |
| BGM匹配 | BGM风格与领域/内容调性匹配 |

### 7.4 成片质量

| 检查项 | 方法 |
|---|---|
| 时长准确 | 实际时长 vs 目标时长 ±10% |
| 字幕同步 | 字幕时间码与配音对齐 |
| 无黑帧 | 所有分镜画面连续 |
| 无静音断裂 | 音频连续无断裂 |

## 10. 验收标准

1. 用户只需 4 步操作（选领域+输入需求+拖图+点生成），30 秒内完成输入。
2. 生成的电商视频有 6 阶段结构（Hook→痛点→产品→卖点→信任→CTA），不是通用口播。
3. 生成的企业视频有 5 阶段结构（Hook→问题→方案→实力→CTA），不是通用口播。
4. 用户上传的图片被智能匹配到对应分镜，不浪费素材。
5. 画面上有设计感文字叠加（价格/卖点/数据/CTA），不是只有底部字幕。
6. 配音音色和 BGM 风格与领域匹配（电商热情/企业专业）。
7. 生成一条 30 秒视频的总耗时 < 3 分钟（快速版）。
