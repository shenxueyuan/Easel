# Easel 企业新媒体与电商内容场景深度开发迭代计划

> 文档类型：现状分析与产品迭代规划
>
> 范围：企业宣传/企业服务新媒体推广、电商商品内容与商品推广
>
> 结论基线：基于当前仓库中的 Web 工作台、112 个 Skill 能力地图、媒体脚本与现有待办梳理。本文不代表某一具体客户的既有需求；“真实诉求”部分用于后续客户访谈、方案售前和产品需求收集，必须以实际企业资料、商品资料、业务数据与合规要求校准。

## 1. 执行摘要

Easel 当前不是单点的"AI 文案/生图工具"，而是一个以账号画像为上下文、以 Agent 编排 Skill、以媒体脚本实际产出文件、并可完成多平台发布与数据复盘的内容生产工作台。它已经具备进入两类场景的基础：

1. **企业新媒体推广**：可覆盖品牌入驻、热点/竞品调研、内容策略、内容日历、图文/视频制作、发布、互动与基础归因。
2. **电商商品内容**：可覆盖卖点文案、商品主图/详情页视觉方案、商品图生成与加工、商品讲解短视频、直播话术、营销活动和多平台分发。

但当前能力的主要形态仍是"通用内容生产能力的组合"，用户需要理解 Skill 名称、手动拼接多步流程。下一阶段的核心方向不是继续横向堆叠更多创意工具，也不是先建复杂的企业级治理系统，而是**把"需求+图片 → 高质量垂直领域视频"这一件事做到极致**。

### 核心理念：极简输入、深度输出

```
用户输入:  需求描述 + 图片素材
            ↓
系统自动:  理解领域 → 写专业脚本 → 智能配图 → 专业配音 → 选曲 → 设计字幕 → 合成
            ↓
用户得到:  高质量垂直领域视频
```

用户操作只需 4 步、30 秒内完成输入：

1. 选择领域：电商宣传 / 企业推广
2. 输入需求：一句话描述要宣传什么
3. 上传图片：拖入产品图/场景图/Logo（可选）
4. 点击生成 → 预览 → 下载

**深度**体现在两个领域各有专用脚本结构、画面策略、配音BGM预设和文字叠加设计：

- **电商宣传视频**：6 阶段转化结构（Hook → 痛点 → 产品亮相 → 卖点展开 → 信任背书 → CTA），画面有价格/卖点/数据叠加，配音热情、BGM 轻快
- **企业推广视频**：5 阶段信任结构（Hook → 问题展开 → 方案介绍 → 实力证明 → CTA），画面有数据/资质/联系方式叠加，配音沉稳、BGM 专业

推荐采用"先做极简生成器验证价值、再按需叠加企业级能力"的路线：先把两个领域的视频生成质量做到客户愿意付费，再根据实际客户需求逐步叠加项目管理、审批、归因等能力。详细技术方案见 [垂直领域视频生成器技术方案](垂直领域视频生成器技术方案.md)。

## 2. 分析范围、事实边界与判断原则

### 2.1 已核对的项目事实

| 维度 | 当前事实 |
|---|---|
| 产品定位 | 面向社交媒体创作者的内容工作台，围绕发现、策划、创作、发布、归因五层工作流运行。 |
| 技能规模 | 能力地图记录为 **112 个 Skill**，覆盖基础、发现、策划、创作、发布、归因六层；前端页面文案显示 113 个 Skill，存在口径不一致，应在后续治理中统一。 |
| 执行模式 | OpenClaw Agent 按需读取 `SKILL.md` 和引用资料，调用脚本/工具执行，而非仅输出建议。 |
| 上下文 | 每个账号/品牌以 Profile 保存身份、风格、受众、平台、偏好与红线、长期记忆六类信息；Web/CLI 将当前画像注入请求。 |
| 交付物 | 内容与中间资产按项目写入 `outputs/`，可在内容库浏览文档、图片、音频、视频与项目元信息。 |
| Web 能力 | 已有对话、画像、热点、选题、日历、内容库、账号、发布与基础数据看板。 |
| 发布能力 | 已接入小红书、抖音、快手、知乎、B 站、微信视频号的登录/发布链路；发布任务有异步状态与历史恢复机制。 |
| 现有待办 | 发布页动态平台、发布确认与后台入口、任务恢复、图文并行生成视频版、BGM 曲库、Wechatsync 回归测试等仍在进行中。 |

### 2.2 本文的判断原则

1. **区分“已经实现”“配置后可用”“需产品化补齐”**。例如 AI 视频、云端配音需要企业自行配置模型服务；平台自动发布还受登录态、平台规则与风控影响。
2. **不将模型生成视为事实来源**。企业介绍、产品参数、价格、功效、认证、库存、优惠规则等必须来自受控事实库或经人工确认。
3. **不把社媒互动等同于业务结果**。播放、点赞、评论是内容层指标；线索、下单、GMV、复购才是企业/电商的经营指标，两者需要数据关联才能用于决策。
4. **不以“Skill 数量”作为行业完成度**。行业产品的验收标准应是客户能否稳定完成一条受控业务链路并得到可审计的结果。

## 3. 当前能力盘点：能做什么、能实现什么效果、技术逻辑是什么

### 3.1 总体技术与内容架构

```text
企业/运营人员
  └─ Web 工作台 / CLI / 自然语言请求 + 上传素材
       └─ 当前品牌或账号 Profile（定位、受众、风格、红线、历史记忆）
            └─ OpenClaw Agent
                 ├─ 按意图选择并读取 Skill 流程与参考资料
                 ├─ 编排发现、策划、制作、发布、归因能力
                 └─ 调用本地脚本、模型 API、浏览器自动化
                      ├─ LLM：理解需求、规划、文案、结果解读
                      ├─ 图片/视频/语音/音乐模型：生成媒体素材
                      ├─ FFmpeg/OpenCV/ASR/图像处理：确定性加工与合成
                      ├─ Playwright/平台工具：登录、发布、数据读取
                      └─ 数据脚本：日志、日历、分析、报告
                           └─ outputs/<项目>/：成品、中间素材、元数据、发布/归因记录
```

这一架构的核心价值是：**生成式模型负责表达与创意，脚本负责可重复的媒体处理和数据计算，画像负责持续一致性，内容项目负责沉淀可复用资产。**

### 3.2 现有端到端内容链路

| 工作层 | 当前能力 | 可实现效果 | 核心技术逻辑 |
|---|---|---|---|
| 发现 | 热点、行业资讯、竞品、UGC、内容缺口、平台/算法变化、事件日历 | 找到可借势但与账号定位相关的选题，而非只罗列热搜 | 聚合公开信息与平台热榜，结合 Profile 赛道/受众/红线过滤，再生成选题建议与风险提示。 |
| 策划 | 品牌入驻、定位、受众、内容支柱、选题矩阵、内容日历、活动/直播/KOL 方案 | 将零散想法形成可执行的内容策略、排期与活动方案 | 结构化访谈与公开信息采集生成 Profile；策略 Skill 按内容支柱、受众路径、渠道分工、KPI 等框架组织输出。 |
| 文字与视觉创作 | 营销文案、长文、卡片、海报、信息图、数据图、商品视觉方案、AI 生图、抠图、增强、批处理 | 得到可预览的 Markdown、HTML、PNG 等成品；支持电商主图/详情页方案 | LLM 生成结构和文案；HTML/CSS 渲染卡片/海报；图像 API 生成素材；Pillow/OpenCV/rembg 等处理尺寸、背景、清晰度与水印。 |
| 音频与视频创作 | 口播配音、声音克隆、字幕、BGM、AI 视频、视频剪辑、切片、画幅转换、相册视频、短剧 | 从主题、脚本或已有素材生成图文、音频和视频成片 | 视频流水线将脚本拆镜，逐镜生成/使用图片或图生视频，TTS/ASR 生成声音与字幕，最后由 `assemble.py`/FFmpeg 合成。 |
| 发布与运营 | 平台适配、质量门禁、排期、一稿多发、发布通知、短链、评论运营 | 将成品转化为各平台草稿/发布任务，集中追踪状态 | 各平台格式规则适配；发布前合规与质量检查；Playwright 或平台 CLI 执行发布；异步 Job 记录逐平台执行结果。 |
| 归因 | 发布日志、账号数据快照、互动/评论洞察、内容复盘、ROI 计算、策略建议 | 得到发布时间、标签、内容类型、增长趋势等运营建议 | 发布记录和账号快照进入 `_analytics` 数据底座；确定性脚本做分桶、聚合和指标计算；LLM 解读结果并给出下一轮建议。 |

### 3.3 品牌与账号上下文能力

当前 Profile 不是简单的昵称配置，而是后续全部内容生成与审核的上下文入口：

| Profile 维度 | 当前承载的信息 | 对企业/电商的作用 |
|---|---|---|
| `identity.md` | 品牌名、定位、使命、差异化、核心产品/服务 | 避免所有内容落成泛行业话术，提供品牌事实与传播主线。 |
| `style.md` | 视觉风格、语气、节奏、Do/Don't、示例文案 | 让不同人员、不同 Skill 产出保持统一调性。 |
| `audience.md` | 目标人群、用户语言、痛点、需求 | 支持按人群选择价值主张、内容主题和表达方式。 |
| `platforms.md` | 平台、账号情况、频率、标签策略 | 为不同平台的内容形态、节奏和分发策略提供依据。 |
| `preferences.md` | 内容支柱、主推对象、禁区、合规底线、目标 | 将企业偏好和禁区显式传给生成与审核环节。 |
| `memory.md` | 后续沉淀的有效经验 | 为持续运营提供历史经验容器。 |

**当前限制**：Profile 更接近“一个品牌/账号的文本画像”，还不是可查询、可版本化、可授权的企业知识库，也无法替代商品主数据、法务批准口径或合同授权资料。

### 3.4 多媒体生产的实际技术路径

#### 3.4.1 图片、卡片和商品视觉

- `ecom-details-image` 可先输出视觉 Brief、转化驱动力诊断、Campaign Style Lock、主图序列、PDP 详情页序列和图片 Prompt；明确生成时再调用生图能力。
- 商品整套视觉默认可规划为 **5 张主图 + 7–9 张详情页图**；多图任务共享色板、字体、背景、光线、布局和图标风格，以减少“每张图像不同品牌”的问题。
- `remove-bg`、`image-editing`、`image-enhance`、`batch-process` 负责白底抠图、比例适配、压缩、加水印、清晰度增强、批量加工等确定性工作。
- `card-design`、`poster-hero`、`comparison-card`、`infographic` 等以 HTML/CSS/本地渲染或图表服务输出结构化视觉物料，适合需要可读文字和稳定版式的营销海报、卖点卡、对比卡、知识卡。

**可实现效果**：从商品/活动描述和参考图出发，形成商品视觉策略、营销海报、主图/场景图、详情页信息图以及社媒内容卡片。

**注意事项**：生成图片中的中文、复杂规格、品牌 Logo、精确商品结构可能出错；必须使用商品实拍/抠图作为参考，关键文字应走可编辑模板或人工复核，不能直接以生图中文字交付上架。

#### 3.4.2 AI 视频与短视频成片

- AI 视频脚本支持文生视频和图生视频，视频服务提供商可配置为通义万相、火山 Seedance、快手可灵、OpenAI 兼容接口、SiliconFlow 等。
- `auto-short-video` 的默认快速模式是“逐句配图 + Ken Burns 缓动”；动态模式则是“每个分镜先出关键帧，再图生视频（I2V）”。
- 一条成片的典型链路是：`video-script` 分镜脚本 → AI 生图或用户素材 → TTS 配音 → 自动字幕 → BGM → `assemble.py` 统一合成。
- 合成器负责画幅补边、镜头运动、字幕烧录、旁白+BGM 混音等，避免每次手写不同的 FFmpeg 命令导致质量不稳定。
- 已有素材还可进行剪辑、横竖版转换、人脸居中裁切、长视频高光切片、绿幕换背景、视频转图文等处理。

**可实现效果**：较快产出适合抖音、小红书视频、视频号、快手等渠道的口播/讲解/商品展示短视频；也可将企业已有拍摄素材重新拆剪为多条分发内容。

**注意事项**：动态版需要逐镜调用视频模型，成本和等待时间显著增加；AI 视频对产品外观、人物口型、品牌标识和连续镜头的一致性有限，商品实拍为主、AI 镜头为辅更符合电商场景质量要求。

#### 3.4.3 配音、音色与音频

- `tts-voiceover` 可按脚本生成口播，并输出分句字幕；未配置云端语音时可退回 Edge TTS。
- 声音克隆采用可插拔云端服务：DashScope CosyVoice、MiniMax、Fish Audio、OpenAI 兼容服务或 Gemini。典型流程是样本登记/引用 → 获得或指定 `voice_id` → 带情绪指令合成。
- `audio-denoise`、`audio-editing`、`audio-mix` 处理降噪、切分、格式转换、音量归一化、旁白+BGM 自动闪避等。

**可实现效果**：企业可以使用经授权的品牌主理人/主播音色，快速为大量内容生成统一旁白，并保留字幕与音频素材。

**注意事项**：声音克隆必须取得声音主体的明确授权，并保存授权期限/用途；不同服务商的声音权利条款、数据留存和可商用范围需要在企业接入前审核。

### 3.5 发布、资产与归因能力

| 模块 | 当前可实现效果 | 技术逻辑 | 现有边界 |
|---|---|---|---|
| 内容库 | 按项目管理图片、视频、音频、文档和中间资产，可预览/下载 | 后端读取 `outputs/` 项目树、元信息与成品路径；前端按媒体类型展示 | 不是企业 DAM，缺素材版权字段、商品关联、版本审批、多人协作。 |
| 平台发布 | 小红书、抖音、快手、知乎、B 站、视频号可登录/发布；可跨平台适配 | Playwright/平台 CLI 与异步发布 Job；前端显示平台状态并支持任务恢复 | 自动化发布受登录、验证码、平台页面变化与风控影响；小红书尤其建议人工确认。 |
| 内容排期 | 管理选题、草稿、待发、已发与活动节点 | 内容日历与发布日志衔接 | 当前是内容排程，未形成企业项目/活动预算/审批排程。 |
| 质量门禁 | 检查敏感词、绝对化用语、医疗违规、平台规则、内容完整性和平台适配度 | 规则库 + Profile/平台上下文 + 结构化审核结果 | 不能代替法务、医疗/金融/广告审查；事实正确性依赖输入资料。 |
| 运营分析 | 记录发布，按时段、标签、内容类型、粉丝变化等分析 | 发布日志、账号快照、确定性分析脚本、LLM 解读 | 目前主要是内容/账号指标；订单、线索、GMV 尚未与内容建立自动关联。 |

## 4. 场景一：企业宣传、企业服务与新媒体推广

### 4.1 企业真正购买的不是“内容”，而是可控的传播能力

企业侧通常有多角色和多目标，不应只按“写一篇文章/做一条视频”接需求。建议将真实诉求拆成以下六类：

| 真实诉求 | 企业希望得到的业务结果 | 需要确认的事实 | 当前能力匹配 |
|---|---|---|---|
| 品牌认知与心智建立 | 让目标客户理解“我是谁、解决什么问题、为什么选我” | 品牌定位、差异化、可信证据、目标行业/人群、品牌禁区 | 强：品牌入驻、定位、内容策略、品牌视觉/文案、矩阵与日历。 |
| 获客与企业服务转化 | 从内容获取咨询、留资、预约、私域线索或销售机会 | ICP、决策链、销售话术、落地页、CRM 字段、转化定义 | 中：可做内容、UTM、短链、ROI 计算；缺 CRM/线索归因闭环。 |
| 招商/招募/雇主品牌 | 建立合作伙伴或人才对企业实力与文化的认知 | 招商政策/岗位事实、地域、资格要求、审批口径 | 中强：视频、图文、活动、KOL 方案可用；需要事实库和审批流。 |
| 新品/服务上线与活动传播 | 在固定节点完成预热、发布、爆发、返场的整合传播 | 上市日期、卖点证据、价格/权益、预算、可用渠道、KOL 资源 | 强：营销活动策划、内容矩阵、多平台制作与分发；缺预算/资源协同管理。 |
| 客户教育与专业信任 | 将复杂服务能力讲清楚，降低销售教育成本 | 服务流程、案例授权、专家身份、可公开数据、行业监管要求 | 强：长文、信息图、案例视频、直播、知识内容；需要知识事实校验。 |
| 舆情、评论与客户沟通 | 及时识别负面问题，给出一致回复与升级机制 | 舆情分级、责任人、标准回复、升级 SLA、禁答问题 | 中：评论洞察、社区运营与风险扫描可用；缺实时监听、工单与审批/升级编排。 |

### 4.2 企业场景的结构化需求采集框架

建议将现有品牌入驻向导升级为“企业传播 Brief”。首轮只收集决定结果的字段，缺失信息标记为待确认，不由模型补造。

#### A. 企业与品牌基础

| 字段组 | 必填字段 | 说明 |
|---|---|---|
| 主体信息 | 企业/品牌名、所属行业、经营区域、官网/官方账号 | 用于识别主体及公开信息核验。 |
| 品牌定位 | 一句话定位、主营产品/服务、差异化、竞争对象 | 形成内容主线与竞争边界。 |
| 可用证据 | 资质、专利/认证、客户案例授权、公开数据、媒体报道 | 所有可用于宣传的事实应给出来源和有效期。 |
| 品牌资产 | Logo、VI、字体、品牌色、图库、视频、历史内容 | 决定视觉一致性与生产效率。 |
| 禁区与审核 | 敏感话题、禁止承诺、法务/品牌审核规则、行业监管 | 在生成前嵌入硬限制。 |

#### B. 目标、受众与转化

| 字段组 | 必填字段 | 说明 |
|---|---|---|
| 本期目标 | 品牌认知、线索、招商、招聘、活动报名、私域、服务咨询等，限选 1–2 个主目标 | 一项内容/活动不应同时承担所有目标。 |
| 目标人群 | 行业、岗位、企业规模、地区、预算、决策角色、核心痛点 | B2B 需区分使用者、影响者、决策者、采购者。 |
| 转化动作 | 点击官网、表单留资、预约演示、添加企微、报名、电话咨询等 | 决定 CTA、短链参数和归因口径。 |
| 成功口径 | 曝光、互动、有效线索、预约、商机、成交中的哪一层指标 | 要明确数据来源、归属周期和负责人。 |

#### C. 内容与渠道

| 字段组 | 必填字段 | 说明 |
|---|---|---|
| 内容支柱 | 如专业洞察、客户案例、产品/服务解释、企业文化、行业热点 | 建议 3–5 个，明确各自承担的受众阶段。 |
| 平台与账号 | 公众号、视频号、抖音、小红书、知乎、B站、LinkedIn 等 | 明确平台角色，而不是同一条内容机械复制。 |
| 内容形式 | 图文、案例长文、短视频、直播、信息图、白皮书、活动物料 | 对应已有制作 Skill 与所需素材。 |
| 发布节奏 | 日常内容频率、节点活动密度、值班和互动响应时间 | 影响产能、人审和发布排程。 |

#### D. 组织与治理

| 字段组 | 必填字段 | 说明 |
|---|---|---|
| 角色 | 需求方、文案、设计、运营、品牌、法务、业务专家、最终发布人 | 是后续 RBAC 和审批工作流的基础。 |
| 审批路径 | 哪些内容需品牌/法务/业务审核，时限与升级规则 | 应从“能发”升级为“谁批准后能发”。 |
| 资料权限 | 哪些资料可用于公开内容、仅内部参考、不可上传第三方模型 | 直接决定数据隔离与模型调用策略。 |
| 风险预案 | 舆情级别、危机声明口径、停发条件与责任人 | 不能只在发布前被动扫描。 |

### 4.3 企业场景的推荐产品化交付包

#### 交付包 A：企业品牌起盘包

- **输入**：企业传播 Brief、历史账号链接、品牌资产、服务/产品事实、2–5 个竞品账号。
- **过程**：品牌建档 → 定位/受众/竞品分析 → 内容策略 → 内容支柱与选题矩阵 → 首月内容日历 → 样稿与视觉模板。
- **输出**：品牌 Profile、品牌事实库初稿、内容策略、平台分工表、内容日历、首批图文/视频样稿、审核清单。
- **效果验收**：不同运营人员基于同一资料生成的内容可保持事实、语气、视觉和禁区的一致；首月内容能对应明确的目标人群与 CTA。

#### 交付包 B：企业服务获客内容包

- **输入**：ICP、典型场景/痛点、服务流程、客户案例授权、线索路径与 CRM 字段。
- **过程**：把“行业问题—解决方案—证据—行动”拆为内容漏斗；生成系列短视频、案例图文、FAQ、直播/活动话术；通过带 UTM 的渠道链接发布。
- **输出**：内容漏斗地图、线索型选题池、素材包、多平台版本、落地页/表单 CTA 文案、渠道追踪方案、月度复盘。
- **效果验收**：每条内容可关联目标人群、CTA、渠道参数与结果；可区分“高互动但无效”与“低曝光但高质量线索”的内容。

#### 交付包 C：企业节点传播/新品服务发布包

- **输入**：节点日期、主目标、核心事实、权益规则、预算/资源、可用渠道、审核人。
- **过程**：活动策划 Skill 输出预热—爆发—返场框架；制作各渠道物料；通过审批和发布任务执行；发布后按阶段复盘。
- **输出**：传播战役 Brief、节奏甘特/日历、内容矩阵、视觉/视频/文案物料、KOL 提案、风险清单、数据看板。
- **效果验收**：活动物料、权益口径和各平台版本一致；每阶段有负责人、发布时间、审批状态和可解释 KPI。

### 4.4 当前能力与企业要求的差距

| 差距 | 风险 | 建议优先级 | 建议方向 |
|---|---|---:|---|
| 企业资料主要为文本 Profile | 容易把过期或未经批准的表述写入内容 | P0 | 建立可版本化事实库，字段包括来源、审批状态、有效期、适用地区/渠道。 |
| 无组织、角色和审批流 | 企业无法明确责任人与最终发布权 | P0 | 建立组织/成员/角色、内容状态机、审批节点、批注和审计日志。 |
| 未区分内容项目、活动项目、客户项目 | 素材、需求、版本、数据容易散落 | P0 | 建立“传播项目”实体，关联 Brief、资产、内容、发布、预算、复盘。 |
| 内容层数据未接 CRM/营销自动化 | 无法证明内容获客贡献 | P1 | 标准化 UTM、落地页/表单事件、线索 ID 回传、渠道归因规则。 |
| 质量门禁主要为通用规则 | 高监管行业/企业声明仍有合规风险 | P1 | 建立行业规则包、敏感声明库、人工法务必审策略和不可自动发布范围。 |
| 竞品/热点能力偏公开内容调研 | 缺行业数据库、销售一线和客户声音 | P1 | 接入可授权的企业知识资料、客服/销售反馈、问答库；数据使用需权限控制。 |

## 5. 场景二：电商商品视频、推广与详情制作

### 5.1 电商真实诉求应围绕“商品经营单元”而非单张图/单条视频

电商客户最终需要的是一套可上架、可投放、可复用、可归因的商品内容资产。应以 SPU/SKU、渠道和营销活动为中心组织需求。

| 真实诉求 | 最终业务结果 | 关键事实/约束 | 当前能力匹配 |
|---|---|---|---|
| 快速上新 | 在短时间内完成可信、统一的商品基础内容 | SPU/SKU、规格、价格、库存、包装、实拍、卖点证据 | 中强：详情文案/视觉、主图、视频可做；缺商品主数据与上架系统连接。 |
| 提升商品点击 | 主图、封面、标题在目标渠道提高 CTR | 平台规范、搜索词、竞品、目标人群、测试样本 | 强：视觉策略、标题、SEO、竞品分析；缺自动化 A/B 实验数据闭环。 |
| 提升详情页转化 | 用户理解价值、消除顾虑并完成加购/下单 | 核心卖点、使用场景、参数、证据、FAQ、售后规则 | 中强：PDP 序列、文案与信息图可做；需要事实校验和渠道模块模板。 |
| 商品短视频/种草 | 用短视频传达场景、演示、对比、口碑与行动 | 产品真实性、实拍素材、脚本、达人/主播出镜授权、画幅 | 强：脚本、混剪、配音字幕、AI 辅助镜头、分发；产品外观一致性需要实拍兜底。 |
| 大促/投放 | 形成多平台、分阶段、可复制的活动物料 | 活动价、券/赠品、起止时间、库存、投放计划、法务口径 | 强：Campaign 策划、多平台物料、短链；缺促销规则版本控制和广告平台数据联动。 |
| 多 SKU 批量内容生产 | 降低商品图文视频的单位生产成本 | 商品表、素材命名、类目模板、差异字段、质量阈值 | 弱到中：有批处理，但没有商品池/任务队列/批量内容编排。 |
| 经营复盘 | 判断哪些内容、素材、卖点真正驱动成交 | 曝光/点击/加购/成交/退款/利润、归因模型 | 弱到中：已有内容/账号分析与 ROI 工具；没有店铺订单级关联。 |

### 5.2 电商商品档案：后续必须新增的结构化输入

现有品牌 Profile 仍应保留，但电商必须新增“商品档案”。建议以 **SPU 为内容策略主体、SKU 为价格和规格事实主体**。

#### A. 商品事实卡（SPU）

| 字段组 | 必填字段 | 说明 |
|---|---|---|
| 商品标识 | SPU 名称、类目、品牌、上市状态 | 所有内容项目必须引用明确商品 ID。 |
| 核心价值 | 目标人群、使用场景、核心痛点、3–5 个经验证卖点 | 卖点必须给出来源或证据等级。 |
| 商品结构 | 材质/成分、尺寸、颜色、包装、使用方法、注意事项 | 用作详情页和视频脚本的事实来源。 |
| 信任证据 | 检测、认证、专利、授权、真实评价、案例 | 必须标明可公开范围、来源、有效期和原文。 |
| 视觉资产 | 白底图、六视图、细节图、场景图、包装图、视频原片、Logo | 包含版权、使用期限、地域/渠道授权。 |
| 内容禁区 | 不可说的功效、禁用词、不得比较对象、不可露出的信息 | 前置给文案、视觉、审核和发布。 |

#### B. SKU/交易规则卡

| 字段组 | 必填字段 | 说明 |
|---|---|---|
| SKU 规格 | SKU 编码、属性组合、条码、尺寸/颜色/容量 | 防止不同款式图文混用。 |
| 交易事实 | 标价、活动价、促销规则、库存状态、售后、发货地/时效 | 应从业务系统同步或由责任人确认，不允许模型猜测。 |
| 渠道映射 | 各平台商品链接、标题限制、图片/视频规范、详情模块要求 | 建立一份商品在多个渠道的发布映射。 |
| 可售状态 | 草稿、待审核、可售、售罄、下架 | 直接决定内容是否可继续生产/发布。 |

#### C. 商品内容 Brief

| 字段组 | 必填字段 | 说明 |
|---|---|---|
| 目标 | 上新、拉新、点击、转化、清库存、复购、活动预热 | 每个内容包只定义一个主目标。 |
| 渠道与位置 | 商品主图、详情页、抖音短视频、小红书种草、广告素材、直播间等 | 同一内容的质量标准随位置不同。 |
| 目标人群与场景 | 谁在什么情境、为解决什么问题购买 | 是脚本、镜头与卖点优先级的依据。 |
| 关键卖点和证据 | 必说/可说/不可说内容，证据来源 | 必须通过事实库校验。 |
| 创意边界 | 风格、参考、禁用元素、是否需要真人/数字人、是否允许 AI 场景 | 保护品牌与商品真实性。 |
| 验收标准 | 画幅、分辨率、时长、文件格式、文字校对、商品一致性、审核人 | 将“好看”转化为可验收条款。 |

### 5.3 电商商品内容包的推荐标准交付物

#### 交付包 A：商品上新基础包

| 模块 | 标准交付 | 复用现有能力 |
|---|---|---|
| 商品定位 | 人群、场景、卖点排序、竞品差异、关键词 | 受众、定位、竞品、SEO、文案能力。 |
| 商品图片 | 白底合规图、5 张主图策略/成品、7–9 屏详情页信息图、尺寸适配版 | `ecom-details-image`、AI 生图、抠图、图片编辑、信息图、批处理。 |
| 商品详情文案 | 标题、首屏价值主张、卖点、参数、使用方式、FAQ、CTA | `copywriting`、`post-formatter`、风险/质量检查。 |
| 商品视频 | 15/30/60 秒脚本、分镜、封面、商品展示/演示视频、字幕与配音版本 | `video-script`、`auto-short-video`、剪辑、字幕、配音、混音。 |
| 渠道版本 | 针对店铺、抖音、小红书、视频号等调整画幅、标题、标签和 CTA | 内容复用、平台适配、发布能力。 |
| 验收包 | 文件清单、版本号、事实来源、审核结论、发布建议 | 当前可部分依托项目产物和质量门禁，需进一步结构化。 |

#### 交付包 B：商品种草与转化短视频包

建议按内容目的，而不是只按“拍一条视频”拆分：

| 视频类型 | 解决的问题 | 核心镜头/结构 | 适合的现有能力 |
|---|---|---|---|
| 痛点引入型 | 让目标用户意识到问题 | 3 秒 Hook → 痛点场景 → 商品解决方案 → CTA | 视频脚本、口播/字幕、短视频合成。 |
| 场景种草型 | 建立“我也需要”的代入感 | 人群/场景 → 使用过程 → 感受/结果 → 种草 CTA | 商品实拍 + AI 补充场景 + 配音/字幕。 |
| 功能演示型 | 证明产品如何使用、如何有效 | 产品特写 → 操作步骤 → 前后对比/数据证据 → FAQ | 已有实拍剪辑、信息图、字幕、配音；避免 AI 虚构效果。 |
| 对比决策型 | 解释型号/方案差异，降低选择成本 | 决策场景 → 维度对比 → 推荐逻辑 → 购买引导 | `comparison-card`、视频脚本、详情信息图。 |
| 口碑/问答型 | 回应常见疑虑，提高信任 | 高频问题 → 真实证据/答复 → 使用建议 → CTA | 评论洞察、FAQ 文案、视频/图文生产。 |
| 大促转化型 | 传达限时权益与紧迫感 | 活动利益点 → 商品卖点 → 规则/库存提示 → 明确行动 | Campaign 策划、海报、商品视频、多平台分发。 |

**推荐制作原则**：商品实拍、录屏、真实演示承担“真实性和细节”；AI 生图/AI 视频主要承担难以拍摄的氛围、转场、概念表达和辅助镜头；参数、价格、优惠、功效和对比结论必须来自商品事实卡。

#### 交付包 C：大促/主题活动内容包

- **输入**：活动目标、时间、参加商品池、规则、价格/赠品、库存阈值、渠道、预算、风险口径。
- **输出**：预热—爆发—返场内容日历；主视觉/海报；活动商品短视频；直播话术；达人/KOL 协作提案；平台版文案；短链与活动参数；复盘模板。
- **必要控制**：促销规则版本号、生效时间、可售库存状态、审核人。任何价格/权益变化都应触发关联内容的“待复审”状态。

### 5.4 电商场景的能力差距与技术补齐方向

| 缺口 | 为什么是关键问题 | 建议补齐方式 | 优先级 |
|---|---|---|---:|
| 商品/SPU/SKU 主数据 | 没有权威商品事实，内容会混款、错价、夸大或使用过期卖点 | 商品中心：商品档案、SKU、规格、卖点、证据、资产、渠道映射、版本与生效时间 | P0 |
| 商品事实校验 | 通用合规扫描无法验证“参数是否真实” | 内容中的数字/宣称/价格/型号须可溯源到事实字段；不匹配则阻断或要求人工确认 | P0 |
| PDP 详情模块化 | 仅靠 Prompt 难保证不同渠道详情页完整、可编辑、可复用 | 建详情模块库：首屏、痛点、卖点、参数、场景、使用、对比、FAQ、信任、售后；按渠道装配 | P0 |
| 商品视频的真实性 | AI 视频容易使产品形态、包装、Logo、细节失真 | 建“实拍资产优先”工作流；镜头引用资产 ID；AI 镜头标识用途；商品一致性审核 | P0 |
| 批量生产 | 多 SKU 客户最关注单位产能、成本与一致性 | 商品 CSV/API 导入、批量任务队列、类目模板、变量填充、失败重试、抽样质检 | P1 |
| 渠道上架/店铺连接 | 只做内容不能减少上架操作和错配 | 先导出标准内容包，再对接优先渠道的商品后台/ERP/PIM（需官方授权接口） | P1 |
| 商品经营归因 | 无法判断内容对成交/利润的影响 | 关联素材版本、商品链接/UTM、广告计划、店铺指标、订单/退款/毛利数据 | P1 |
| 素材权利与达人授权 | 商业使用、肖像、音乐、商品图版权均有风险 | 素材资产增加来源、授权范围、期限、地域、可用渠道、到期预警字段 | P1 |
| 创意实验系统 | 缺少“哪个卖点/封面/脚本更好”的证据 | 创意变量库、实验分组、版本标签、渠道指标回流、停止规则 | P2 |

## 6. 两大场景共用的目标产品模型

### 6.1 从“通用对话”升级为“四类业务对象”

| 业务对象 | 企业新媒体场景 | 电商场景 | 必要能力 |
|---|---|---|---|
| 品牌/账号 | 企业品牌、区域品牌、雇主品牌、专家 IP | 店铺品牌、子品牌、达人账号 | Profile、品牌资产、平台、风格、红线、成员权限。 |
| 事实库 | 服务、案例、资质、行业数据、活动权益 | 商品、SKU、参数、价格、功效证据、售后、库存状态 | 结构化字段、来源、有效期、审批、检索、版本。 |
| 项目 | 品牌月度运营、获客专题、发布会、招商活动 | 商品上新、单品推广、大促、店播内容 | Brief、目标、预算、排期、责任人、内容与数据关联。 |
| 内容资产 | 图文、白皮书、案例视频、海报、直播脚本 | 主图、详情模块、商品视频、封面、投放素材 | 版本、素材引用、渠道规格、审核、发布、表现数据。 |

### 6.2 统一内容状态机

建议将现在的草稿/待发/已发扩展为如下状态，适用于两类场景：

```text
需求待澄清
  → Brief 已确认
  → 生成中
  → 初稿待审
  → 修改中
  → 事实/合规审核中
  → 已批准待排期
  → 已发布/已导出
  → 数据回流中
  → 已复盘 / 已归档
```

关键规则：

1. 价格、参数、功效、案例、活动权益等受控字段发生变化时，关联内容自动标记为“需复审”。
2. 未通过审批的内容只可预览/导出草稿，不可自动发布。
3. 每次发布必须记录内容版本、使用的商品/事实版本、渠道、发布时间、操作者和结果。
4. 每次数据回流必须能关联到内容版本、渠道和业务对象，防止“同名内容”污染复盘。

### 6.3 共用的人机协同原则

| 环节 | AI 应承担 | 人必须承担 |
|---|---|---|
| 需求梳理 | 追问缺失字段、输出 Brief、发现冲突 | 确认事实、目标、预算、授权和优先级。 |
| 策略/创意 | 生成多种方向、选题、脚本、视觉方案 | 选择方向，确认是否符合品牌和业务策略。 |
| 内容制作 | 自动生成初稿、适配尺寸、批量处理、生成预览 | 审阅商品/企业真实性、中文文字、审美和最终品质。 |
| 合规 | 命中规则、发现风险词和缺失字段、生成修改建议 | 法务/品牌/行业专家作最终判断，尤其高风险行业。 |
| 发布 | 执行格式适配、任务提交、状态回传 | 账号安全、人工确认、验证码处理、最终发送权限。 |
| 复盘 | 汇总指标、找模式、给假设和下轮建议 | 判断因果、结合销售/市场一线信息作资源决策。 |

## 7. 下一阶段迭代路线图

> 不以自然周承诺排期，而以"每阶段的可验收门槛"推进。先做极简生成器验证价值，再按需叠加企业级能力。

### 阶段 0：聚焦与验证设计（产品立项门槛）

**目标**：选择清晰的首批客户与最小闭环，完成数据、合规、交付标准的定义。

| 工作项 | 企业新媒体 | 电商 | 产出/验收 |
|---|---|---|---|
| 目标客户分层 | 选择 B2B 企业服务、品牌营销或区域企业中的一个优先子类 | 选择美妆/服饰/家居/食品/数码等一个类目优先验证 | 明确 ICP、决策人、现有工作流、预算与主要痛点。 |
| 需求访谈 | 访谈市场、销售、品牌、法务、运营 | 访谈商品、视觉、店铺、投放、主播/客服 | 每类至少形成一份真实需求样本与现有流程泳道图。 |
| 交付标准 | 定义"一条企业推广视频"的固定交付标准 | 定义"一条电商宣传视频"的固定交付标准 | 画幅、时长、脚本结构、画面质量、配音BGM、文字叠加规范明确。 |
| 风险分级 | 明确敏感行业、客户案例、宣传口径的审核规则 | 明确价格/功效/食品/美妆/医疗器械等内容边界 | 风险清单、禁止自动发布场景、人工终审角色。 |
| 指标基线 | 收集历史内容、线索、人工工时 | 收集商品内容制作时长、CTR/CVR、退货/投诉等 | 后续对比以基线而非主观感受判断价值。 |

**阶段门槛**：每个优先场景至少有 3 个真实需求样本；客户明确哪些数据可使用、哪些事实为唯一权威源、谁对发布与合规负责。

### 阶段 1：垂直领域视频生成器（优先投入）

**目标**：让用户只需"需求描述 + 图片素材"，即可得到高质量的垂直领域视频。用户无需理解 Skill 名称，无需填写复杂表单。

总操作 4 步，30 秒内完成输入。

### 阶段 2：企业级治理与经营数据闭环

**目标**：让系统从“高效制作工具”变为“可被企业长期采用的业务协同系统”。

| 能力主题 | 关键需求 | 验收标准 |
|---|---|---|
| 多租户与权限 | 企业、项目、品牌、商品、素材、账号维度的隔离；管理员/运营/设计/法务/发布人等角色 | 越权用户无法看到或发布不属于自己的资产；所有敏感操作可追溯。 |
| 审批与版本 | 内容/素材版本、批注、比较、退回、审批 SLA、引用事实版本锁定 | 任一已发布内容可定位“谁在何时批准了哪个版本”。 |
| 资产与授权管理 | 素材标签、来源、版权、肖像/声音授权、使用范围、到期预警 | 到期或用途不匹配的素材不可进入发布候选。 |
| 数据连接 | UTM/短链、表单/CRM、店铺/广告数据、订单/商品指标的数据接入 | 可在内容—渠道—线索/订单链路上查看可解释数据。 |
| 归因看板 | 内容、活动、商品、平台、版本、卖点等维度的指标比较 | 能支持“保留/加码/停止哪种内容”的真实经营决策。 |
| 可靠发布 | 平台账号健康、失败原因、重试/人工接管、发布确认与告警 | 发布状态不因页面刷新丢失；失败不会被误报为成功。 |

**阶段门槛**：一条发布内容可完整回放其需求、事实、素材、审批、发布和结果；企业可用权限和审核满足内部协作要求。

### 阶段 3：规模化生产与持续优化

**目标**：服务多品牌、多商品、多渠道、多活动的高频生产，并让数据驱动创意迭代。

| 能力主题 | 重点建设 | 价值 |
|---|---|---|
| 批量商品工厂 | SKU 导入、类目模板、变量填充、队列、成本预算、失败重试、抽样质检 | 显著降低大商品池内容生产的单位成本。 |
| 模板与组件库 | 企业内容模板、PDP 模块、镜头模板、品牌视觉组件、活动模板 | 从“每次重新生成”变为“受控复用+局部创意”。 |
| 创意实验 | 封面/Hook/卖点/CTA/视觉风格版本的实验设计和指标回流 | 将经验转为可验证的增长假设。 |
| 推荐与排产 | 基于库存、活动、趋势、历史表现推荐优先商品、内容和渠道 | 提升资源投入的经营效率。 |
| 外部系统集成 | PIM/ERP/OMS/CRM/CDP、店铺/广告/客服系统的官方或授权接口 | 消除数据和人工搬运断点。 |
| 行业规则包 | 美妆、食品、医疗健康、金融、教育、招商等行业专项校验 | 扩大适用行业同时控制风险。 |

**阶段门槛**：批量任务可监控、可恢复、可审计；系统能利用历史数据推荐策略，但所有推荐可解释、可人工覆盖。

## 9. 关键技术设计建议

### 9.1 数据模型优先于 Prompt 扩张

应避免只在每个新场景新增一个更长的 Prompt。推荐将受控业务信息落为实体：

```text
Organization
  ├─ Member / Role / Permission
  ├─ BrandProfile
  │    ├─ BrandFact (source, approval, effective_period)
  │    ├─ BrandAsset (license, territory, channel, expiry)
  │    └─ SocialAccount
  ├─ ProductSPU
  │    ├─ ProductSKU
  │    ├─ ProductFact (claim/evidence/version)
  │    └─ ProductAsset
  ├─ Campaign / ContentProject
  │    ├─ Brief
  │    ├─ ContentAsset (version, format, channel spec)
  │    ├─ Review / Approval
  │    ├─ PublishTask
  │    └─ PerformanceMetric
  └─ Template / Experiment
```

Profile 仍作为 Agent 的高层上下文；事实库作为生成、校验、审批的权威输入；项目则是所有资产和数据的关联单位。

### 9.2 内容生成采用“检索—计划—生成—校验—审批”的受控链路

```text
结构化 Brief
  → 检索已批准的品牌/商品事实与资产
  → 生成内容计划（卖点、渠道、形式、镜头、引用）
  → 人确认计划或系统按风险策略放行
  → 生成文案/图像/视频/适配版本
  → 自动校验（事实、规格、文字、尺寸、规则、版权状态）
  → 人工审核和批注
  → 发布/导出
  → 数据回流与复盘
```

这样可保留当前 Agent+Skill 的灵活性，同时让企业关键内容不依赖模型“记住”资料。

### 9.3 模型策略与成本控制

| 任务类型 | 推荐策略 | 原因 |
|---|---|---|
| Brief、策略、文案、审核解释 | LLM 为主，引用事实库 | 成本可控、可快速迭代，但需事实约束。 |
| 商品主图、Logo、包装、细节 | 实拍/设计源文件优先，AI 用于背景、场景、辅助创意 | 保证商品一致性和可商用可控性。 |
| 信息图/PDP 文字页 | 模板渲染优先，AI 生成内容变量 | 避免 AI 图片中的中文与参数错误。 |
| 商品视频 | 实拍/录屏/素材库为主；AI I2V 用于补充氛围和转场 | 平衡真实性、成本和生产速度。 |
| 高风险宣称 | 模型不得自动扩写或推断 | 必须来源可追溯并由人工批准。 |
| 批量任务 | 队列、预算上限、缓存/复用、失败重试、抽检 | 防止高额模型调用和不可控产出。 |

### 9.4 平台与发布可靠性

当前发布能力是重要优势，但企业化前应明确：

1. 平台自动化是**受平台页面、账号状态、验证码和风控影响的辅助能力**，不能承诺 100% 自动发布成功。
2. 必须以“平台已确认”区分“已提交”“待确认”“已发布”；现有 TODO 中也已将此作为验收原则。
3. 发布任务需要保留幂等标识、完整日志、人工接管和重试入口，避免重复发帖或误判成功。
4. 高风险账号、重要节点、敏感行业内容默认采用“人工审核 + 人工最终确认”模式。

## 10. 指标体系与验收方法

### 10.1 产品效率指标

| 指标 | 定义 | 目的 |
|---|---|---|
| Brief 完整率 | 必填业务字段和事实字段的填充比例 | 避免垃圾输入造成垃圾输出。 |
| 首稿可审率 | 无需返工到完全重做、可进入审核的内容比例 | 衡量生成质量与模板成熟度。 |
| 单内容包交付周期 | 从 Brief 确认到通过审核/导出的时间 | 衡量客户感知效率。 |
| 人工编辑时长 | 人工从首稿到可用成品的时间 | 识别 AI 真正节省的工作量。 |
| 资产复用率 | 引用既有合规资产/模板的比例 | 衡量品牌一致性和边际效率。 |
| 发布任务成功率 | 按“平台已确认发布”计算的成功比例 | 衡量链路可靠性，不能把已提交当成功。 |

### 10.2 企业新媒体业务指标

按“认知—信任—行动—商机”分层：

| 层级 | 例示指标 | 数据来源 |
|---|---|---|
| 认知 | 覆盖、曝光、播放、搜索量、粉丝净增 | 平台数据。 |
| 信任 | 完播、收藏、深度阅读、正向评论、案例内容互动 | 平台数据、评论分析。 |
| 行动 | 官网点击、表单提交、活动报名、企微添加、咨询 | UTM/短链、表单、CRM。 |
| 商机 | MQL、SQL、商机金额、成交周期、获客成本 | CRM/销售系统。 |

### 10.3 电商业务指标

按“内容质量—流量—交易—利润”分层：

| 层级 | 例示指标 | 数据来源 |
|---|---|---|
| 内容质量 | 商品事实错误率、图片/视频质检通过率、审核一次通过率 | 系统审核与人工抽检。 |
| 流量 | 主图 CTR、视频 3 秒留存/完播、搜索曝光、进店率 | 店铺/内容/广告平台。 |
| 交易 | 商品 CVR、加购率、成交件数、GMV、客单价 | 店铺/订单系统。 |
| 利润与长期价值 | ROAS、毛利、退款率、差评率、复购率 | 广告、ERP/OMS、客服/评价数据。 |

### 10.4 归因原则

1. 将内容分析视为**相关性分析**，不直接将“标签/时段表现好”视为因果结论。
2. 对投放与活动，记录内容版本、素材版本、渠道、预算、UTM、商品/落地页，才具备实验与归因条件。
3. 样本不足时必须标注统计不确定性；不要用少量爆款推导全局策略。
4. 对企业服务的长销售周期，使用多触点归因或至少记录“首次触达/关键触达/转化”三个节点，而非只看最后一次点击。

## 11. 风险、边界与治理要求

| 风险类型 | 典型问题 | 控制措施 |
|---|---|---|
| 事实与虚假宣传 | AI 编造参数、认证、效果、销量、案例或价格 | 受控事实库、来源引用、字段校验、禁止模型补全、人工终审。 |
| 行业合规 | 医疗、食品、美妆、金融、教育、招商等有专项限制 | 行业规则包、风险分级、法务必审、不可自动发布清单。 |
| 商品真实性 | AI 图/视频中的产品形态、包装、Logo 与实物不一致 | 实拍资产优先、商品一致性审查、关键镜头人工检查。 |
| 知识产权 | 图片、音乐、字体、达人素材、客户案例使用超范围 | 素材授权台账、渠道/地域/期限约束、到期预警。 |
| 声音与肖像 | 克隆主播或客户声音未经授权 | 明确授权、用途限制、期限管理、撤回/删除机制。 |
| 数据与隐私 | 客户资料、未发布产品、订单/CRM 信息外泄 | 数据分级、最小权限、脱敏、第三方模型调用策略、操作审计。 |
| 平台风控 | 自动化发布被验证、限流、账号异常 | 人工确认、账号健康检查、失败不误报成功、人工接管。 |
| 生成成本 | 批量生图/逐镜视频导致费用失控 | 预算、配额、预估、确认、队列和缓存；快速版/实拍优先。 |
| 组织协作 | 多人同时修改、口径不一致、责任不清 | 版本、审批、锁定、批注、角色和项目负责人。 |

## 12. 建议的首批试点方式

### 12.1 企业新媒体试点

- **推荐试点对象**：有明确品牌资产、已有 1–3 个社媒账号、内容生产依赖人工且希望获客的 B2B 企业服务或专业服务企业。
- **试点项目**：选择一个服务专题或新品/活动节点，完成从企业 Brief、内容策略、4 周内容日历、图文/短视频物料、发布、线索追踪到复盘的闭环。
- **试点重点**：验证事实库/审核是否真的减少返工，验证内容是否能关联有效咨询或线索，而非只验证“能生成内容”。

### 12.2 电商试点

- **推荐试点对象**：商品资料和实拍资产较完整、有 10–50 个可运营 SKU、正在进行上新或大促的品牌店/商家。
- **试点项目**：选择 3–5 个商品，建立商品档案，分别完成上新基础包与种草短视频包，并针对一个渠道做主图/封面/卖点的版本测试。
- **试点重点**：验证商品事实错误率、首稿可审率、单 SKU 交付时长、素材复用率，以及 CTR/CVR 等业务数据的变化。

### 12.3 试点结束后的决策问题

1. 哪一类客户愿意为“可信、可审核、可归因的内容生产”付费，而不只为单次生成付费？
2. 哪个行业/类目能最少依赖特殊数据接入，也能最快体现交付效率和业务价值？
3. 哪些内容类型最容易实现模板化和资产复用？
4. 哪些事实/合规审核环节是最大阻塞，应该优先产品化？
5. 发布自动化在哪些平台和客户上稳定可用，哪些必须保留人工终审？

## 13. 最终结论

Easel 已经拥有成为企业内容运营与电商商品内容生产平台的良好技术底座：Agent 编排、112 个跨环节 Skill、画像上下文、多媒体生产、项目产物、真实发布与基础归因已经覆盖了内容生命周期的大部分"制作能力"。

下一阶段最应该做的不是继续横向堆叠更多创意工具，也不是先建复杂的企业级治理系统，而是**把"需求+图片 → 高质量垂直领域视频"这一件事做到极致**：

1. **电商宣传视频链路**：需求描述 + 产品图 → 6 阶段转化脚本 → 智能配图 + 价格/卖点/CTA 文字叠加 → 领域配音BGM → 合成成片；
2. **企业推广视频链路**：需求描述 + 场景图 → 5 阶段信任脚本 → 智能配图 + 数据/资质/CTA 文字叠加 → 领域配音BGM → 合成成片。

用户操作只需 4 步、30 秒内完成输入。先把这两个领域的视频生成质量做到客户愿意付费，再根据实际客户需求逐步叠加项目管理、审批、归因等企业级能力。详细技术方案见 [垂直领域视频生成器技术方案](垂直领域视频生成器技术方案.md)。
